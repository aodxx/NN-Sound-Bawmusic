# Phase 4.1 — Overnight Booking Test Plan

ทดสอบกับสำเนา Google Sheets ก่อนฐานข้อมูลจริงเสมอ และตั้ง Spreadsheet/Apps Script timezone เป็น `Asia/Bangkok`

## Migration

1. Deploy `code.gs` รุ่นใหม่เป็น Web App version ใหม่
2. เรียก API หรือเปิดหน้า Admin หนึ่งครั้งเพื่อให้ migration ทำงาน
3. ตรวจชีต `Bookings`
   - มีคอลัมน์ `endDate` ต่อท้ายเพียงหนึ่งคอลัมน์
   - แถวเดิมที่ `endDate` ว่างถูกเติมให้เท่ากับ `date`
   - ข้อมูลเดิมทุกคอลัมน์ยังอยู่ตำแหน่งเดิม
4. ตรวจชีต `Settings`
   - `bookingBufferBeforeMinutes` = `120`
   - `bookingBufferAfterMinutes` = `120`
5. งานเก่าที่ `startTime > endTime` ต้องตรวจและแก้ `endDate` ด้วยแอดมินให้เป็นวันถัดไป

## Required scenarios

ใช้ข้อมูลทดสอบที่ไม่ชนกับงานจริง:

1. งานปกติ
   - วันที่เริ่มและสิ้นสุดวันเดียวกัน
   - เวลา `18:00–22:00`
   - ต้องบันทึกและแสดงในปฏิทินวันเดียว
2. งานข้ามวัน
   - วันที่เริ่ม 1 สิงหาคม เวลา `20:00`
   - วันที่สิ้นสุด 2 สิงหาคม เวลา `01:00`
   - ต้องบันทึกได้และแสดงในปฏิทินทั้งสองวัน
3. งานเช้าวันถัดไป
   - หลังงานข้อ 2 ให้ลอง `02:00–06:00` ต้องแจ้งชนเพราะอยู่ใน buffer
   - ลอง `05:00–09:00` ต้องว่างเมื่อใช้ buffer ก่อน/หลัง 120 นาที
4. ไม่กรอกเวลา
   - เว้นเวลาเริ่มและสิ้นสุดว่างทั้งคู่
   - ระบบต้องตีความเป็นเต็มวัน และแจ้งชนกับงานอื่นในวันนั้น
5. เวลาข้ามเที่ยงคืนแต่ไม่เลือกวันถัดไป
   - วันที่เริ่มและสิ้นสุดวันเดียวกัน เวลา `20:00–01:00`
   - ระบบต้องไม่ยอมบันทึกและบอกให้เลือกวันที่สิ้นสุดเป็นวันถัดไป

## Regression

- Admin: สร้าง แก้ไข ยืนยัน ยกเลิก และเปิดใบสรุปงาน
- Google Sheets: ค่า `date`, `endDate`, `startTime`, `endTime` ตรงกับฟอร์ม
- LINE LIFF: ตรวจคิว ส่งคำขอ และเปิด Customer Portal
- LINE Messaging: ยืนยันงานแล้ว Flex Message แสดงช่วงวันที่ถูกต้อง
- PWA: ปิด–เปิดใหม่แล้วฟอร์มมีช่องวันที่สิ้นสุด ไม่ติด cache รุ่นเก่า

ห้าม Merge จนกว่าการทดสอบ Apps Script Deployment, Google Sheets และ LINE LIFF จริงครบทุกข้อที่เกี่ยวข้อง
